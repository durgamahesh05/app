# Backend

## Run locally

Use Conda for local development. `environment.yml` creates a clean environment with Python 3.10 and installs the packages from `requirements.txt`:

```powershell
cd backend
conda env create -f environment.yml
conda activate merizo-backend-py310
python --version # should report Python 3.10.x
Copy-Item .env.example .env # only when .env does not already exist
```

If you already have a Conda environment named `.venv`, activate it instead of creating another one: `conda activate .venv`. Confirm it reports Python 3.10.x with `python --version`, then run `python -m pip install -r requirements.txt` after activating it.

Set `MONGODB_URL`, `MONGODB_DATABASE`, and a private `JWT_SECRET` with at least 32 characters in `.env`. Keep `.env` out of source control. Start the API with:

```powershell
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

The API provides authentication/profile routes, group create/list/join/member lookup, expense create/list/delete/split updates, settlement create/history, friends derived from shared groups, and monthly expense insights. All these feature routes require the bearer token returned by login. Group invite codes are generated by the API. Expenses created without a group are personal to their creator.

| Method | Route | Purpose |
|---|---|---|
| POST | `/api/auth/register`, `/api/auth/login` | Register and sign in |
| GET | `/api/users/profile`; POST `/api/users/update` | Read and update the signed-in profile |
| POST | `/api/groups/create`, `/api/groups/join`; GET `/api/groups/list`, `/api/groups/members?group_id=...` | Create, join, list, and inspect group members |
| POST | `/api/expenses/create`, `/api/expenses/split`; GET `/api/expenses/list`; DELETE `/api/expenses/delete` | Record, split, list, and remove expenses |
| POST | `/api/settlements/create`; GET `/api/settlements/history` | Record payments and view expense/payment activity |
| GET | `/api/friends/list` | List people from shared groups and their net balances |
| GET | `/api/insights/summary`, `/api/insights/analytics` | Monthly totals based on the signed-in user's expense shares |

Registration creates an active account; email OTP verification is not configured. The forgot-password and OTP screens still need an email delivery service before those flows can work. Receipt extraction, AI chat, and push notifications also need provider integrations and are not implemented backend features yet.

MongoDB collections used are `users`, `groups`, `expenses`, and `settlements`. Set up a new database as described above; indexes on user email are created when the API connects.

## Run with Docker

With Docker Desktop running and `backend/.env` configured, start the API from the project root:

```powershell
docker compose up --build backend
```

The API is available at `http://localhost:8000` (Swagger UI: `http://localhost:8000/docs`). The Compose service reads settings from `backend/.env`; the Docker build excludes that file. Stop it with `docker compose down`.

The Docker image uses Python 3.10 as well, so local Conda and container environments run the same Python minor version.
